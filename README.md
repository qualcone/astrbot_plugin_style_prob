## 简介

把"偶尔使用某种表达方式"写进人设提示词，是常见做法，但效果很难控制：

- 模型对"偶尔""适度"这类频率描述没有稳定的理解，同一条提示在不同轮次、不同模型、不同上下文长度下，表现可能差别很大；
- 往往是要么几乎不出现，要么反复出现，且难以调节——改一个措辞，频率就整体漂移；
- 频率无法量化，也就无法复现、对比和调参。

本插件把"这一轮要不要出现"从模型的隐式判断中拿出来，改成**由插件按可配置的概率决定**：只在被选中的轮次才向模型追加一句指令，其余轮次模型完全不受影响。同时用一个判定模型检查回复里风格是否真的出现，形成闭环：出现了就让概率回落，没出现就逐步提高概率，从而把整体频率稳定在目标附近。

人设里不再需要写任何频率相关的描述，频率由档位或参数直接控制，可以用数值预测，也可以随时调整。该机制与具体风格无关，指令内容完全由你定义：语气、口癖、表情、格式、话题引导等均可。

## 特性

- **频率可控**：低 / 中 / 高三档预设，或自定义初始概率、上限和爬升速度；
- **闭环调节**：判定模型检查风格是否真的出现，出现则重置，未出现则概率递增；
- **缓存友好**：指令只加在本轮用户消息末尾，不改动 system prompt 与历史消息；
- **默认不污染历史**：以临时内容块注入，指令不会写入会话历史；
- **不阻塞回复**：判定在后台异步执行，失败或超时只记日志，不影响对话；
- **状态持久化**：每个会话的计数重启后保留，修改设置后可一键清空；
- **效果可验证**：预期与实际触发次数对比、显著性检验、遵循率与样本量参考；
- **输入有保护**：所有数字配置都做范围校验，无效值自动回退并提示；
- **无第三方依赖**：仅使用标准库，Linux / Windows / macOS 均可运行。

## 工作原理

1. **请求前**：按当前概率 p_k 对本轮抽样；命中则把风格指令追加到本轮用户消息的末尾。
2. **回复后**：计数 k 加 1，随后在后台异步地让判定模型检查回复中是否出现了该风格。
   - 出现 → k 重置为 1，概率回到初始值 p_0，并记录这一次的触发间隔；
   - 未出现 → 保持，概率继续按曲线上升。
3. 判定不会阻塞回复发送。判定失败、超时或结果无法解析时，不改变状态，只记日志。

没有被注入的消息同样让 k 加 1，对应"距上次触发已经过了多少条消息"。

### 概率曲线

自上次触发后的第 k 条消息（k 从 1 开始）的注入概率：

```
p_k = min(p_max, p_0 + (p_max - p_0) * (k - 1) / n)
```

概率从 p_0 线性上升到 p_max，共 n 步，之后保持 p_max。
由这条曲线可以直接算出平均触发间隔和每 100 条消息的预期触发次数（`/风格概率`）。
该数值是"被注入"的理论值：模型不一定完全遵循指令，实际出现频率通常更低。

## 安装

**要求**：AstrBot ≥ 4.9.2（使用默认的 `temp_part` 注入方式需 ≥ 4.24，低版本自动回退），Python ≥ 3.12（AstrBot 本身的要求）。

**方式一：通过 AstrBot 面板安装**

在 AstrBot 管理面板的「插件」页面选择「从链接安装」，填入仓库地址：

```
https://github.com/qualcone/astrbot_plugin_style_prob
```

**方式二：手动安装**

```bash
cd AstrBot/data/plugins
git clone https://github.com/qualcone/astrbot_plugin_style_prob.git
```

然后在面板中重载插件或重启 AstrBot。目录名必须保持为 `astrbot_plugin_style_prob`。

## 快速开始

1. 在插件配置页填写「风格指令文本」，例如 `（本条回复请使用更轻松、口语化的语气。）`；
2. 选择「出现频率档位」，默认为中档；
3. （推荐）在「判定模型提供商」中选一个便宜的小模型；
4. 发几条消息后，用 `/风格状态` 查看计数与当前概率，用 `/风格自测` 验证模型是否遵循指令。

## 频率档位

内置低、中、高三档预设，也可选"自定义"手动指定 p_0 / p_max / n：

| 档位 | p_0 → p_max（n） | 平均间隔 E[T] | 每 100 条预期被注入 | 一半情况下多久内出现 |
|---|---|---|---|---|
| 低 | 0.02 → 0.15（30） | 约 15.7 条 | 约 6.4 次 | 14 条内 |
| 中（默认） | 0.05 → 0.35（20） | 约 8.1 条 | 约 12.4 次 | 7 条内 |
| 高 | 0.15 → 0.70（10） | 约 3.8 条 | 约 26.2 次 | 4 条内 |

仅选择“自定义”时，配置页才会显示 `p0`、`p_max`、`ramp_steps` 三项；选择低 / 中 / 高时这三项被隐藏且不参与计算（已填写的值会保留，切回自定义后仍在）。可用 `/风格概率` 查看当前设置的理论数值。
旧版 AstrBot 的配置页若不支持条件显示，这三项会始终可见，但行为一致。

## 注入位置与缓存

指令只会加在**本轮用户消息的末尾**，不会修改 system prompt，也不会改动任何历史消息。
大模型的缓存按前缀匹配，system prompt 位于最前面，改动它会使整段历史的缓存失效；
只在最后一条用户消息之后追加，前面的内容保持不变，缓存基本不受影响。

提供两种注入方式（`inject_mode`）：

| 方式 | 是否写入历史 | 缓存影响 | 要求 |
|---|---|---|---|
| `temp_part`（默认，推荐） | 否，仅对本轮请求生效；用户原话与机器人回复照常保存 | 被注入那一轮的下一轮，从该条用户消息起有一小段缓存需要重算，更早的历史不受影响 | AstrBot ≥ 4.24，不可用时自动回退为 `prompt` |
| `prompt` | 是，随该消息写入历史 | 后续轮次前缀完全一致，缓存命中最好 | 无；但模型会在历史中看到过去几轮的风格指令，可能影响后续表现 |

## 配置项

| 配置项 | 含义 |
|---|---|
| 是否启用 `enabled` | 总开关。 |
| 风格指令文本 `style_instruction` | 命中时追加到用户消息末尾的指令，内容完全自定义。 |
| 注入方式 `inject_mode` | `temp_part`（默认）或 `prompt`，见上文。 |
| 出现频率档位 `intensity` | 低 / 中 / 高 / 自定义，默认中。 |
| 初始概率 `p0` | 仅自定义档。触发后第 1 条消息的注入概率（0~1）。 |
| 最高概率 `p_max` | 仅自定义档。概率上限（0~1）。 |
| 上升步数 `ramp_steps` | 仅自定义档。从 p_0 升到 p_max 所需的消息条数 n。 |
| 判定模型提供商 `judge_provider` | 用于判定的模型，建议选择成本低的小模型；留空则使用当前会话的聊天模型。 |
| 判定提示词 `judge_prompt` | 自定义"什么算触发"。支持占位符：`{instruction}` 风格指令、`{reply}` 机器人回复、`{user}` 用户消息（需开启下一项）。要求模型只回答"是"或"否"；留空使用内置模板。 |
| 判定时附带用户消息 `judge_include_user` | 开启后判定提示中包含用户那一句。判定调用始终**不带历史对话**。 |
| 关键词快速判定 `keyword_hints` | 可选。回复中出现任一关键词即直接判定为"出现"，不调用模型；未命中时仍交给判定模型。适用于特征词明确的风格。 |
| 仅在注入时判定 `judge_only_when_injected` | 开启：仅当本轮注入了指令才判定，节省调用。关闭：每轮都判定，模型自发出现的风格也会重置概率。 |
| 判定超时 `judge_timeout` | 判定调用的超时秒数。 |
| 生效范围 `scope_mode` | `all`：对全部会话生效；`persona`：仅在使用所选人设的会话中生效；`session`：仅对所选会话生效。不在范围内的会话不注入、不计数、不判定。 |
| 指定人设 `scope_persona` | 仅“指定人设”模式显示，通过人设选择器选择**一个**人设。按会话**当前实际使用的人设**判断，会话中切换人设后立即按新人设重新判断；无法确定人设时按不生效处理。 |
| 指定会话 `scope_sessions` | 仅“指定会话”模式显示。填写会话标识（`unified_msg_origin`），每行一个，可在目标会话中用 `/sid` 查看。 |

## 指令

| 指令 | 说明 | 权限 |
|---|---|---|
| `/风格概率` | 输出当前设置的 E[T] 与每 100 条消息的预期注入次数；若已有实测数据，附上实测的间隔个数与平均值，便于与理论值对照。 | 所有人 |
| `/风格统计` | 对比预期与实际的触发次数，给出显著性检验、遵循率和样本量参考，见[效果统计](#效果统计)。 | 所有人 |
| `/风格状态` | 查看当前会话的计数 k、当前注入概率，以及全局累计统计。 | 所有人 |
| `/风格重置` | 仅重置**当前会话**的计数（k = 1，概率回到 p_0）。 | 所有人 |
| `/风格清空` | 清空**所有会话**的计数与全部统计数据，各会话从 k = 1 重新开始。 | 管理员 |
| `/风格自测 [次数]` | 实测模型是否遵循指令、判定模型是否可靠，见下文。 | 所有人 |

### 自测

`/风格自测 [次数]`（默认 3，最多 10）使用**固定的**测试指令与测试消息，不读取你的配置，保证每次检验的是同一件事：

- 测试指令：`请在回复的每一句话末尾都加上“喵~”。`（特征明确，是否遵循一目了然）；
- 测试消息：5 条日常问句，轮流使用。

对每条消息各请求一次"注入指令"和"不注入"，用内置判定模板与当前判定模型检查，最后给出两组的出现次数对比，
正常情况应接近 `n/n` 对 `0/n`。该测试使用当前会话的聊天模型直接生成（不带人设与历史），
不改动任何会话的计数，也不经过 `temp_part` 注入通道本身。

## 效果统计

`/风格统计` 用于回答"实际效果是否达到预期"：

- **触发次数**：预期值 = 已统计的回复条数 ÷ 平均触发间隔，与实际"判为出现"的次数对比，并给出相对偏差；
- **显著性检验**：判断差异是正常的随机波动，还是确实存在偏差（p < 0.05 视为显著），并说明方向：
  显著偏低通常意味着模型没有完全遵循指令或判定偏严，显著偏高则可能是模型自发出现了该风格或判定偏松；
- **遵循率**：被注入的轮次中，风格确实出现的比例，附 95% 置信区间；
- **平均触发间隔**：实测值与理论值对照；
- **判定失败次数**：判定模型超时或报错的次数，过多会让结果偏低。

### 需要多大样本

触发是低频事件，样本太少时，次数的上下波动本身就很大，不足以下结论。
按 95% 置信、80% 把握来估算，要可靠地看出实际与预期的偏差，大致需要累计的触发次数为：

| 想看出的偏差 | 需要累计触发次数 | 对应消息条数（低 / 中 / 高档） |
|---|---|---|
| ±30% | 约 30 次 | 约 500 / 250 / 110 条 |
| ±20% | 约 70 次 | 约 1100 / 560 / 240 条 |
| ±10% | 约 280 次 | 约 4500 / 2200 / 980 条 |

经验法则：**至少累计 30 次触发再看结论**；想把偏差判断精确到 10%，需要约 280 次。
预期触发数不足 30 次时，`/风格统计` 会提示样本太少，数字仅供参考。
统计汇总所有会话，因此活跃度越高的部署越快攒够样本。
`/风格统计` 的末尾会按当前设置列出各偏差水平所需的次数和当前进度。

## 数据存储

插件使用 AstrBot 的插件 KV 存储持久化数据，**重启后不丢失**：

- **每个会话的计数 k**：群聊与私聊各自独立保存，即"现在触发到哪了"；
- **全局统计**：累计注入次数、判定次数、判为出现的次数，以及最近至多 5000 个实测触发间隔；
- **会话索引**：用于"清空全部"。

数据按 `作者/插件名`（`qualcone/astrbot_plugin_style_prob`）隔离，修改 `metadata.yaml` 中的作者或名称会导致已有数据读取不到。

### 修改设置之后

各会话的计数 k 会继续沿用，概率按新设置计算。例如从低档切到高档时，k 已经很大的会话会立刻按高档的上限概率抽样，这是预期行为。

但统计数据是基于旧设置累计的，混在一起算"预期值"会得出误导性的结论。因此插件会记录统计所基于的设置（档位 / 概率参数 / 风格指令），
一旦发现与当前设置不一致，`/风格统计` 只展示原始计数，**不再做预期对比和显著性检验**，`/风格状态`、`/风格概率` 也会提示。
此时可用 `/风格清空` 清除全部数据重新累计，或用 `/风格重置` 只重置某个会话。

## 数值范围与校验

所有数字配置都会校验，无效值不会导致报错，也不会影响正常对话：自动改用默认值，并在 `/风格状态` 里以 ⚠ 提示具体哪一项有问题。

| 配置项 | 合法范围 | 无效时 |
|---|---|---|
| 初始概率 `p0` | 0 ~ 1 的小数（填 0.05，不是 5 或 5%） | 改用 0.05 |
| 最高概率 `p_max` | 0 ~ 1 的小数 | 改用 0.35 |
| 上升步数 `ramp_steps` | 0 ~ 10000 的整数（配置页滑块 0~1000） | 改用 20 |
| 判定超时 `judge_timeout` | 1 ~ 300 的整数秒 | 改用 30 |
| `/风格自测` 的次数 | 1 ~ 10 的整数 | 超出范围按边界值处理，无法识别时用 3 |

补充规则：

- `p_max` 小于 `p0` 时，按 `p0` 处理（概率恒定），并提示；`p0` 和 `p_max` 都为 0 表示永不触发；
- 非数字、空值、NaN、无穷大、负数、超出范围的值都视为无效；`0.3` 和 `"0.3"` 都能识别；
- 会话列表、关键词列表中混入的非文本项会被忽略；开关项填 `"false"` / `"0"` 等也能正确识别；
- 风格指令为空时插件不注入任何内容，`/风格状态` 会提示；
- 持久化数据损坏（类型不对）时按空数据处理，不会抛异常；
- 插件自身出错时放行本轮请求，不会中断正常对话。

## 常见问题

**设置了概率，实际出现得比预期少？**
概率决定的是"是否注入指令"，模型不一定每次都照做。用 `/风格统计` 查看遵循率；遵循率偏低时，可以把指令写得更具体、更明确。

**为什么不直接在人设里写"偶尔……"？**
见[简介](#简介)：模型对频率描述的理解不稳定，且无法量化与调节。

**判定模型会增加多少调用？**
默认"仅在注入时判定"，只有被注入的那一轮才多一次小模型调用。关闭该选项后每轮都会判定。

**判定模型挂了会影响聊天吗？**
不会。判定在后台执行，失败或超时只写日志，且不改变状态。

**怎么让它只在某个人设下生效？**
把“生效范围”设为“指定人设”，在“指定人设”中选择目标人设即可。判断依据是会话当前实际使用的人设，与聊天模型无关；判定模型则在“判定模型”中单独设置。

**多个会话的计数会互相影响吗？**
不会。每个会话独立计数，只有 `/风格统计` 的全局汇总会合并各会话的数据。
